# Asset and verification checklist

## Required before implementation

- [ ] Approved public email
- [ ] Approved phone visibility
- [ ] Exact LinkedIn URL
- [ ] Approved portrait or hero artifact
- [ ] Nomambhoy publication permission and public URL
- [ ] Journal Portal publication permission and public URL
- [ ] Blog App publication permission and public URL
- [ ] EPathshala publication permission and public URL
- [ ] One real screenshot for every featured project
- [ ] Mobile crop or responsive screenshot where relevant
- [ ] Verified role and timeline for each project
- [ ] Verified metrics with measurement context
- [ ] Confirmation of what eSewa work may be described publicly

## Media acceptance rules

- Images must have stable dimensions and a clear focal point.
- Screenshots must show real product behavior, not invented placeholder UI.
- Redact secrets, customer data, internal URLs, tokens, and private dashboards.
- Use descriptive alt text for informative images.
- Mark purely decorative images with empty alt text.
- Keep original source files outside the web bundle when they are only working references.

## Link verification

- [ ] Portfolio domain
- [ ] GitHub profile
- [ ] LinkedIn profile
- [ ] Project repositories
- [ ] Live demos
- [ ] Email link
- [ ] Contact interaction: mailto or verified form endpoint
- [ ] Contact form recipient inbox, spam protection, privacy copy, success state, and error state if a form is used
- [ ] Any downloadable resume link
- [ ] Decision on whether X and Instagram should be linked publicly

## Content risk review

- [ ] No confidential employer details
- [ ] No private client names
- [ ] No fabricated performance numbers
- [ ] No unsupported AI claims
- [ ] No technology listed solely for decoration
- [ ] No duplicated or contradictory email addresses
